# ADR-008 认证与会话基线

## 元数据（Metadata）

- 状态：Accepted
- 关联架构章节：3. 运行模式与集成；7. 安全与可观测性基线

## 架构对齐（Architecture Alignment）

本 ADR 对上述相关架构章节具有规范性约束作用。

## 背景（Context）

当前实现以 Cookie 承载 access token，已取消 refresh/session 机制。  
需要将生产鉴权策略固定为不可绕过的硬约束，避免运行期配置漂移。

## 决策（Decision）

1. 统一采用 JWT access token 认证，token 通过 HttpOnly Cookie 传输。
2. `JWT_EXPIRES_IN` 必须满足 `s/m/h/d` 格式，且不得超过 24h。
3. 生产环境必须提供强 `JWT_SECRET`，禁止默认弱密钥。
4. 鉴权严格模式固定启用，不提供 `AUTH_GUARD_STRICT` 等可关闭开关。
5. 缺失、过期、非法 token 均返回确定性 `401` 语义。

## 备选方案（Alternatives）

1. Access + refresh 双 token：复杂度更高，当前阶段不采用。
2. 长时 access token：风险较高，不采用。

## 影响（Consequences）

正向影响：
1. 认证链路更简单，状态面更小。
2. 生产安全策略不依赖运维临时开关。

负向影响：
1. 服务重启后需要重新登录。
2. 长会话体验依赖 access token TTL 的平衡配置。

## 回退触发条件（Rollback Triggers）

1. 合规或产品需求明确要求恢复 refresh/session。
2. 认证复杂度与安全目标发生结构性变更并通过架构评审。

# ADR-009 运维安全与可观测标准

## 元数据（Metadata）

- 状态：Accepted
- 关联架构章节：7. 安全与可观测性基线；9. 当前已知约束与缺口

## 架构对齐（Architecture Alignment）

本 ADR 对上述相关架构章节具有规范性约束作用。数据库在网络上的可达范围、测试环境认证强度与云侧暴露面由 **ADR-014** 单独约束，本 ADR 的日志与审计要求在不与之冲突的前提下适用。

## 背景（Context）

缺少统一日志审计与告警标准会降低故障处理效率。

## 决策（Decision）

1. 生产 Web 流量强制 HTTPS/TLS。
2. 统一结构化日志基线：请求链路使用 `requestId`，异常响应执行脱敏。
3. 审计日志输出覆盖关键字段（事件、请求、身份、结果）并支持请求链路追踪。
4. 生产明文 HTTP 请求固定拒绝，不提供 env 降级开关。
5. 关键资产（models/templates）在启动阶段执行存在性校验，失败即终止启动。
6. 主机与容器资源监控应能支撑异常 CPU、陌生进程及非常规路径可执行文件类告警，作为 ADR-014 所述入侵征兆的运维补强（具体工具与阈值由部署环境选定）。

## 备选方案（Alternatives）

1. 各服务自行定义日志：灵活但不可聚合。

## 影响（Consequences）

正向影响：
1. 可观测性一致。
2. 审计合规性提升。

负向影响：
1. 需要统一日志治理成本。

## 回退触发条件（Rollback Triggers）

1. 监控平台替换导致标准需整体改版。

# ADR-002 前后端技术栈基线

## 元数据（Metadata）

- 状态：Accepted
- 关联架构章节：3. 运行形态；4. 传输与认证语义；5. 数据与持久化

## 架构对齐（Architecture Alignment）

本 ADR 对上述相关架构章节具有规范性约束作用。

## 背景（Context）

需统一前后端与 electron 技术栈，减少重复逻辑和工具链分裂。

## 决策（Decision）

1. 前端基线：`React + TypeScript + Vite + React Router + Redux Toolkit + Ant Design + axios`。
2. 后端基线：`NestJS（@nestjs/platform-express） + TypeScript + Zod`，主协议为 HTTP(S) REST。
3. 数据访问基线：Server 侧采用 `Drizzle ORM + pg`（Postgres），Electron 侧采用 SQLite。
4. Redis/MQ 当前默认不引入，仅在明确触发条件满足时评审引入。

## 备选方案（Alternatives）

1. 延续历史栈：短期改动少，长期维护成本高。
2. web/electron 使用不同前端框架：局部优化但一致性差。

## 影响（Consequences）

正向影响：
1. 开发体验统一。
2. 契约优先架构更易落地。
3. 测试与 CI 门禁更稳定。

负向影响：
1. 存在迁移成本。
2. 团队需要学习当前默认栈与约定。

## 回退触发条件（Rollback Triggers）

1. 合规或平台限制要求更换核心框架。
2. 长期运行证据显示该栈不可维护。

# PRD-003 打印前审核员密码校验对齐 Web 与 Electron

## 1. 目标

将记录页“打印前审核确认”能力从仅 Electron 扩展为 Web 与 Electron 一致启用，确保两端都需完成审核员选择与密码校验后才可继续打印。

## 2. 背景

- 现状中，打印前审核员选择与密码验证仅在 Electron 生效，Web 端默认可直接打印。
- 业务希望 Web 与 Electron 在打印责任确认流程保持一致，避免端间行为差异带来的合规风险。
- 当前页面已具备审核员选择、密码弹窗和校验逻辑，可复用并扩展到 Web 端。

## 3. 范围

### In Scope

- 记录页打印确认流程在 Web 与 Electron 统一要求：
  - 选择审核员；
  - 输入并验证审核员密码；
  - 校验通过后才允许点击“确认打印”。
- 用户列表加载逻辑从“仅 Electron”改为“有机构信息时两端均加载”。
- 打印确认弹窗中的审核员展示改为两端统一使用审核员下拉选择。

### Out of Scope

- 后端用户鉴权策略与密码规则调整。
- 打印 PDF 模板内容改版。
- 审核员角色体系与权限模型变更。

## 4. 设计说明

### 4.1 契约与类型

- 本次不新增请求/响应契约字段。
- 复用既有审核员登录校验接口与记录实体字段（`reviewerName`）。

### 4.2 服务端（Postgres）

- 不涉及数据库结构变更。
- 若现有接口已支持审核员密码校验与记录更新，按既有契约调用。

### 4.3 Electron（SQLite）

- 保持既有 Electron 行为不变。
- 与 Web 端对齐为统一的打印前审核员确认流程。

### 4.4 前端交互

- 打印确认弹窗中，审核员字段统一展示为可选下拉框（两端一致）。
- 选择审核员后弹出密码输入框，校验成功后标记审核通过。
- “确认打印”按钮在以下任一条件成立时禁用：
  - 正在打印中；
  - 审核员未完成密码校验。
- 页面初始化时，在有机构信息且用户列表为空时，触发审核员列表加载（不再限定 Electron）。

## 5. 兼容性与风险

- 兼容性：不改变打印 PDF 生成逻辑，仅增强前置校验。
- 风险：
  - Web 端若未正确加载用户列表，会导致无法选择审核员并阻断打印；
  - 用户误选审核员或密码错误会增加一次交互成本，但符合流程要求。

## 6. 预期测试

### 6.1 单元/类型检查

- [ ] Frontend typecheck 通过。
- [ ] Frontend lint 通过。

### 6.2 功能测试（核心场景）

- [ ] Web 端点击打印，默认不可直接确认打印，需先完成审核员密码校验。
- [ ] Electron 端原有打印前审核流程仍可正常使用。
- [ ] 选择审核员并输入正确密码后，可点击“确认打印”并成功打开预览。
- [ ] 输入错误密码时，提示错误，且“确认打印”保持不可用。

### 6.3 边界场景

- [ ] 用户列表为空时，审核员下拉不可选，打印按钮保持禁用。
- [ ] 取消审核员密码弹窗后，审核状态被重置，需重新选择并校验。
- [ ] 重复打开/关闭打印确认弹窗后，审核员状态不脏读（每次重新确认）。

## 7. 验收标准

- Web 与 Electron 的打印前审核流程一致：都需审核员密码校验通过后方可打印。
- 未完成审核员校验时，不能继续打印。
- 已有打印预览能力与其余记录页操作不受影响。
- 前端构建与基础检查通过，无新增 lint/type 错误。

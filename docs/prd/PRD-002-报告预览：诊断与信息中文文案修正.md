# PRD-002 报告预览：诊断与信息中文文案修正

## 1. 目标

修复报告预览（ReportPreviewer）诊断页与信息页中中文显示的占位/乱码字符问题，提升用户理解与可读性。

## 2. 背景

- 诊断结果与性别字段在当前 UI 中出现异常字符（看起来像编码占位符），影响业务人员快速判断。
- 同一套报告预览组件需要在不同终端（Web/Electron）保持一致的展示语义与可读性。

## 3. 范围

### In Scope

- 修正诊断页 `DiagnosisBlock` 中“评估结果”字段的中文展示（将显示从异常字符替换为明确的中文语义，如“无转移/有转移”）。
- 修正信息页 `InfomationBlock` 中患者性别字段的中文映射（将 `m`/其它性别值映射为“男/女”）。
- 相关组件中与上述展示直接相关的文案占位符/显示文本进行统一替换。

### Out of Scope

- 评估阈值逻辑、结果计算方式的调整。
- 后端契约与数据结构变更。
- 数据库与接口层改动。

## 4. 设计说明

### 4.1 契约与类型

- 本 PR 不引入新的请求/响应契约字段。
- 仅对前端展示层的文案进行替换与映射修正。

### 4.2 服务端（Postgres）

- 不涉及服务端与数据库改动。

### 4.3 Electron（SQLite）

- 不涉及本地数据库结构改动。
- 本 PR 仅改变 Electron 运行时中所依赖的前端展示文本映射。

### 4.4 前端交互

- 诊断页：根据既有的 `record.result` 与既有阈值判断逻辑，输出更明确的中文文案。
- 信息页：根据 `record.patientGender` 的现有值，输出更明确的中文性别文案。

## 5. 兼容性与风险

- 兼容性：不改动业务计算逻辑与契约字段，属于展示层变更。
- 风险：
  - 如果 `record.patientGender` 取值域与现有映射不一致，可能出现性别显示偏差；需核对后端/数据源的枚举取值。
  - 文案替换可能影响截图/快照测试，需要同步更新期望值。

## 6. 预期测试

### 6.1 单元/类型检查

- [ ] Frontend typecheck 通过。
- [ ] Frontend lint 通过。

### 6.2 功能测试（核心场景）

- [ ] 在报告预览诊断页展示“评估结果”时，确认无异常字符，且显示为明确中文语义。
- [ ] 在报告预览信息页展示性别时，确认 `m` 显示为“男”，其它性别值显示为“女”（或符合实际取值逻辑）。
- [ ] 验证上述字段在不同记录数据组合下均无乱码/占位符残留。

### 6.3 边界场景

- [ ] `patientGender` 为 `n/a` 等特殊值时，仍显示为 `-`，不引入新异常。
- [ ] `record.result` 在阈值附近时，仍能正确走到对应中文文案分支。

## 7. 验收标准

- 报告预览诊断页“评估结果”中文显示正确、无乱码字符。
- 报告预览信息页性别显示正确、符合预期映射。
- 现有构建/类型检查/基础 lint 通过。

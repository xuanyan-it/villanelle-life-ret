# PRD-004 报告生成患者信息缺失展示为（无）

## 1. 目标

在报告生成场景中，统一“患者姓名 / 患者年龄 / 其他信息”字段的缺失态渲染规则：当对应值缺失时，前端显示为“（无）”，避免空白内容影响阅读与打印确认。

## 2. 背景

- 当前报告生成页面中，患者相关字段在缺失数据时可能显示为空字符串、`null`、`undefined` 或空白区域。
- 医护/审核人员在预览与打印时，无法快速判断是“未录入”还是“渲染异常”。
- 业务期望对缺失信息采用一致占位文案“（无）”，提升可读性与一致性。

## 3. 范围

### In Scope

- 报告生成相关页面内以下字段缺失时展示“（无）”：
  - 患者姓名；
  - 患者年龄；
  - 其他信息。
- 缺失判定覆盖常见空值：`null`、`undefined`、空字符串、仅空白字符。
- 多语言场景下，中文文案采用“（无）”。

### Out of Scope

- 后端数据清洗、默认值回填策略调整。
- 报告模板字段增减与结构改版。
- 非上述三个字段的缺失态策略统一。

## 4. 设计说明

### 4.1 渲染规则

- 当字段值为以下任一情况时，UI 展示“（无）”：
  - 值不存在（`null` / `undefined`）；
  - 去除首尾空白后为空字符串。
- 当字段有有效内容时，按原值展示，不改变既有格式。

### 4.2 文案与本地化

- 中文环境缺失占位文案为“（无）”。
- 建议将缺失占位文案纳入 i18n 资源，避免硬编码。

### 4.3 兼容性

- 仅影响前端显示层，不改变接口请求/响应契约。
- 不影响已存在的导出、打印流程逻辑。

## 5. 风险与注意事项

- 若仅在部分组件实现占位，可能导致同一字段在不同页面表现不一致。
- 年龄字段若存在 `0`，需确认业务语义：`0` 应视为有效值而非缺失值。

## 6. 预期测试

### 6.1 基础检查

- [ ] Frontend lint 通过。
- [ ] Frontend typecheck 通过。

### 6.2 功能测试（核心场景）

- [ ] 患者姓名缺失时显示“（无）”。
- [ ] 患者年龄缺失时显示“（无）”。
- [ ] 其他信息缺失时显示“（无）”。
- [ ] 字段存在有效值时，正常显示原内容。

### 6.3 边界场景

- [ ] 字段值为仅空白字符（如 `"   "`）时显示“（无）”。
- [ ] 年龄值为 `0` 时按有效值显示（若业务确认有效）。
- [ ] 打印预览、导出时与页面渲染一致。

## 7. 验收标准

- 报告生成中“患者姓名 / 患者年龄 / 其他信息”三项在缺失数据时均展示“（无）”。
- 三项字段在有效数据下不受影响，维持原有展示。
- 前端基础检查通过，无新增 lint/type 错误。

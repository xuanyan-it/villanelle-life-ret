# PRD-001 记录检索：患者名或样本编号

## 1. 目标

为记录列表增加检索能力，支持用户按“患者名”或“样本编号”进行快速查询，并保持 Web 与 Electron 行为一致。

## 2. 背景

- 当前记录列表仅支持分页与回收站切换，不支持关键词检索。
- 实际使用中，操作员需要在大量记录中快速定位单个患者或样本。
- 同一套业务需要同时覆盖 Web（Server + Postgres）与 Electron（本地 SQLite）运行时。

## 3. 范围

### In Scope

- `record/list` 请求新增可选参数 `searchKeyword`。
- 后端 Postgres 列表查询支持按 `patientName` / `sampleId` 模糊匹配。
- Electron 本地 SQLite 查询支持同等模糊匹配。
- 前端记录页新增搜索输入框并接入列表刷新流程。
- 中英文 i18n 文案补充搜索占位符。

### Out of Scope

- 高级筛选（例如按日期区间、检测结果、检测员筛选）。
- 拼音/同义词检索、全文索引优化。
- 搜索历史、快捷筛选标签。

## 4. 设计说明

### 4.1 契约与类型

- 在共享契约 `BaseRecordListRequestSchema` 中新增 `searchKeyword?: string`。
- 共享 Domain 端口 `RecordRepositoryPort.list` 新增 `searchKeyword?: string`。
- 前端 API 类型、Redux 请求参数同步新增该字段。

### 4.2 服务端（Postgres）

- 在 `listRecords` 条件中保留既有 `instituteName` 与 `isDeleted` 过滤。
- 当 `searchKeyword` 非空时，追加：
  - `patient_name ILIKE '%keyword%'`
  - `sample_id ILIKE '%keyword%'`
  - 两条件使用 `OR` 连接，并作为总条件的一部分。
- 空关键词时保持原查询逻辑不变。

### 4.3 Electron（SQLite）

- 在 `fetchSampleRecords` 中，关键词非空时为 SQL 添加：
  - `(patientName LIKE ? OR sampleId LIKE ?)`
- 关键词参数统一通过 `%keyword%` 传入。
- 空关键词时保持原查询逻辑不变。

### 4.4 前端交互

- 在记录页顶部新增 `Input.Search`：
  - 支持回车或点击搜索按钮触发；
  - 支持清空输入。
- 搜索提交时：
  - 更新 `record.searchKeyword`；
  - 重置分页到第 1 页；
  - 清空已选中行；
  - 触发列表重新请求。
- 列表请求参数自动携带 `searchKeyword`。

## 5. 兼容性与风险

- 兼容性：`searchKeyword` 为可选字段，旧调用方不传时行为不变。
- 风险：
  - 模糊查询在超大数据量下可能增加数据库压力；
  - `LIKE/ILIKE` 方案当前满足功能性，后续可按容量评估引入索引优化。

## 6. 预期测试

### 6.1 单元/类型检查

- [ ] Shared 类型构建通过（契约变更可编译）。
- [ ] Server typecheck 通过。
- [ ] Frontend typecheck 通过。
- [ ] Electron typecheck 通过。

### 6.2 功能测试（核心场景）

- [ ] 输入患者名关键字，返回包含该患者名的记录。
- [ ] 输入样本编号关键字，返回包含该样本编号的记录。
- [ ] 输入不存在关键字，返回空列表，且总数为 0。
- [ ] 清空关键词后，列表恢复默认分页结果。
- [ ] 检索条件下切换回收站视图，结果仍按关键词 + 删除状态过滤。
- [ ] 检索条件下分页切换，结果连续且无重复/缺失。

### 6.3 边界场景

- [ ] 关键词前后空格被正确 trim。
- [ ] 关键词大小写差异（Postgres）可命中（`ILIKE`）。
- [ ] 空关键词不应改变原有查询结果。
- [ ] 删除/导出/查看详情等已有操作在检索结果中行为不变。

## 7. 验收标准

- 用户可在记录页按患者名或样本编号完成检索。
- Web 与 Electron 检索行为一致。
- 不传 `searchKeyword` 时功能与历史版本一致。
- 现有类型检查通过且无新增 lint 错误。
